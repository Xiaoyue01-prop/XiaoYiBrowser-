# Notify Me V0.3.2 — Shared Google authentication (multi-account preview)

Supersedes V0.3.1 owner-only instructions. All Google accounts with a correctly signed ID token for the configured Summit OAuth web client may sign in. The verified immutable `sub` is the identity (not email). The server issues a seven-day signed nm2 session for `summit-services`. Android reuses its existing Google profile and encrypts the session with Keystore. No admin key is included in APK. The account endpoint `/v1/account` currently reports `plan: preview`, `billingEnabled: false`, `services.notifyMe: true`. This is an authentication foundation, not an implemented Football endpoint, subscription verifier, or cross-Worker SSO. Future services must verify the session and server-side entitlements before accessing provider APIs.

## Deployment order (same Worker and database)
1. In D1 Console for `summit-notify-db`, execute `tools/notify-me-ai/migration-v2.sql` in its entirety. It is additive and can be run more than once. Existing `watches`, `events`, and `ai_usage` remain unchanged. The new account-owned tables are `notify_watches_v2`, `notify_events_v2`, `notify_ai_usage_v2`. The old global records are not automatically assigned to a Google identity: they were unowned and cannot be safely mapped. Existing beta watches can be analyzed and registered again; the original rows remain available to the database administrator for a separately verified migration. Do not delete the old tables.
2. In Worker Edit code, replace code with `tools/notify-me-ai/worker.mjs` (distributed as worker.js). Deploy. Keep `BETA_TOKEN`, `AI`, `DB`, `ALLOWED_HOSTS` and the existing OAuth client ID. `OWNER_GOOGLE_EMAIL` and `OWNER_GOOGLE_SUB` are now ignored and can be removed. Do not set `ENABLE_NOTIFY_CRON` yet. A distinct secret for session signing and revocable sessions should be considered before broad public release.
3. Test root version `0.2.2-google-multi`, then existing admin `/v1/health` with the private token. Admin bearer now supports health endpoints only, not user records. AI health test consumes one of the shared daily calls. Build/install Android APK V0.3.2; old nm1 sessions and tickets cannot be reused. Sign into Summit with Google; confirm the matching Google account on the first Notify Me request. Test two independent accounts following the same URL and confirm their lists stay separate. Keep Cron disabled.

## Controls and limitations
- All validated Google accounts currently have the same preview access. No Free/Pro limits or payments are implemented. For operational protection, shared AI cap remains 20 calls/day UTC, with 10 calls per account/day and 100 watches per account (hard technical ceiling, not a paid tier). These counts are not a guarantee of Cloudflare neuron quota or capacity. A rejected global budget attempt may consume one account budget slot. No arbitrary public-host fetch: retain explicit ALLOWED_HOSTS, HTTPS only, bounded input and no redirects/query tokens. User tokens cannot call administrative AI health or read other accounts' records. Analysis tickets bind the verified account. The existing observe endpoint trusts that account's reported observation; before background operation and public rollout, verify observations or add stronger abuse protections.
- No server-side forced revocation of individual sessions yet; rotating BETA_TOKEN invalidates all sessions/tickets. Local sign-out clears the encrypted session. Before wide distribution add auth/request rate limits at edge (including login), session revocation, independent security review, retention/deletion controls, load/CPU/quota tests. No deduplication of website polling across accounts yet. Cron explicitly disabled by default, and WorkManager/FCM/Instant Open/real Live Update are not integrated by this patch.
- Real Google login, Android build, Keystore, Cloudflare deployment and quota behavior are not tested here. Local tests use signed JWT fixtures, SQLite and mocked AI/HTML. See tools/notify-me-ai/TEST-RESULTS.txt and EXTRACTOR-RESULTS.txt.
