If preview changed/expired, analyze again. In Following, Đồng bộ danh sách reads D1; Bỏ theo dõi deletes a selected watch and events after confirmation. Closing the Sheet clears local data and token; watch remains in D1.
6. Check D1 with `SELECT id, title, kind, latest, status FROM watches;` (omit URLs when sharing logs). Health endpoints remain as in V0.1.1. Xem sau and the old Live Update probe remain explicitly DEMO. No automatic monitoring is enabled by the Android build.

## Security and scope
- Private owner only. Server cap 10 watches, 20 AI calls/day including health tests, fixed 60-minute interval + 15-minute fallback grace in DB. Config and all /v1 routes require owner token. Signed receipt is a short-lived integrity check for this owner flow, not independent authentication; same owner secret is used for signing, and confirmation still validates public HTML. Replaying a valid receipt for an existing watch returns that watch. A deleted watch could be recreated by deliberate replay before expiry. No broad SSRF-safe arbitrary-host design or per-user accounts yet.
- API /v1/analyze is preview-only. POST /v1/watches now requires `{ticket:{data,mac}}` instead of metadata payload. Existing SQL schema unchanged. Existing polling/observe/event/cron backend routes retained, but leave Cron off until Android WorkManager/event delivery is ready. No local persistent watch cache, encrypted watch storage, background token storage, WorkManager, FCM, real notification actions, or Instant Open in this stage. The three switches and interval remain visual controls only, explicitly marked as such; they do not change the server schedule.
- Native network client restricts routes and fixed HTTPS worker origin, disallows redirects, bounds response and request size, avoids logs and persistence. Cancellation prevents UI updates after dismissal; an already transmitted HTTP request may still finish server-side. Refresh Following after reconnect if uncertain. No token embedded in APK. Existing security/GlassSystem/BrowserBottomSheet left unchanged.
- Extractor supports limited selectors (safe CSS class/id + anchor) and numbered chapter/episode text; the user approves metadata before transmission. Public source validation is not a semantic guarantee; manually verify result.
